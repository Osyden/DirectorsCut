# Offline erosion kernel: first implementation

Owner: Codex cliff worker. New standalone tools only: `Tools/generate_eroded_cliff_sector.py` and `Tools/test_eroded_cliff_sector.py`. No runtime geometry, materials, imports, Unreal process or GPU work. The separate seed exporter owns the actual crater surface/frame and protection bounds; root owns mesh export, Nanite and visual acceptance.

Input NPZ requires matching 2D float32 `height_m`, `bedrock_m`, `erodibility` and `protected_mask`, plus positive scalar `cell_size_m`. Height is absolute metres in the supplied frame. `protected_mask == 1` is bitwise fixed, including signed zero; partial protection slows erosion/deposition/thermal transfer. Bedrock is an immutable erosion floor. Optional `loose_m` provides movable surface sediment; otherwise at most 0.5 m of initial loose cover is weighted by erodibility and mobility. Origin/basis/raw-profile metadata arrays pass through unchanged. Object/pickled metadata is rejected.

The original NumPy algorithm uses available-water-limited D8 downhill hydraulic-head flux, conservative suspended-sediment advection, flow/slope-dependent sediment capacity, and bounded erosion/deposition. Hydraulic erosion is limited by erodibility, bedrock and a per-step cell-size fraction. Conservative thermal flux moves only tracked loose material above the repose slope; it cannot cross a fully protected cell. Boundaries are closed, with no wraparound. Evaporated water is budgeted. Suspended material is retained in the output rather than discarded or artificially deposited at the end.

Output preserves the seed fields/frame and replaces `height_m`, adding `eroded_m` and `deposited_m` (gross thickness, including thermal movement), `flow_accumulation` (cumulative outgoing water volume in m3), `flow_mask` (log-normalized 0..1), `slope` (inclination normalized 0..1), `slope_degrees`, `curvature` (signed bounded mask), `curvature_m_inv`, and `water_m`, `suspended_m`, `loose_m`. `metrics_json` reports mass budgets, extrema, protection count, timing and settings. `erosion_metadata_json` describes units and limits. Solver checks run before float32 serialization; serialized solid-mass error must remain inside the measured rounding bound.

Use existing NumPy-capable Python: `E:/Utilities/Blender/5.3/python/bin/python.exe` (NumPy 2.3.4). The blender_mcp virtualenv does not contain NumPy; no environment was changed. Example: `python Tools/generate_eroded_cliff_sector.py --input actual_sector.npz --output Saved/Erosion/actual_eroded.npz --steps 256 --seed 71421`. Input/output paths must differ. `--demo-size 128` explicitly creates and labels a synthetic test slope, never an actual crater. Generated results stay under ignored `Saved/Erosion`.

Validation: `python Tools/test_eroded_cliff_sector.py` passes seven tests covering 128-square transport, fixed-pad bits, input immutability, conservation, deterministic seed, hard rock, loose-only thermal movement, bedrock bounds and invalid input. The 128-square/128-step demo took 0.16 s, with solid-mass error -1.16e-10 m3 and water error 3.55e-11 m3. The 512-square/256-step demo took 23.68 s while other work was active; solid solver error 0 m3, water error 2.21e-9 m3, serialized solid error -0.01397 m3 within its 12.23 m3 float32 rounding bound. Reservoir minima were nonnegative. These are demo performance/numerical results, not rendered crater validation.

Limits: this is accelerated morphology, not calibrated rainfall timing, shallow-water momentum, cavitation or a full fluid solver. A heightfield cannot represent overhangs; the seed exporter must document any upper-envelope conversion. Closed boundaries and protected bottom edges pond water and sediment; they must not be mistaken for a natural outflow. D8 transport retains grid-direction bias. There is no fracture mechanics, lithology evolution or automatic artistically good composition. Outputs are completed seed runs, not a resumable fluid simulation: a fresh call resets water and suspended reservoirs. Start from the immutable supplied seed for comparisons. The next acceptance step is to run the actual exported sector, inspect erosion/flow/deposition masks and verify protected skyline/toe bounds, then let root render the resulting mesh.
